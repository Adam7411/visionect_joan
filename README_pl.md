## Recommended setup (AppDaemon)

Most users keep the tablet on a **single AppDaemon HADashboard** generated by the **[Joan Dashboard Generator](https://github.com/Adam7411/joan_generator)** add-on:

```
joan_generator (GUI) → *.dash in AppDaemon → http://<HA>:5050/Dashboard?widget=…
Tablet session URL   → same AppDaemon URL (set once)
visionect_joan       → device ops: battery, recovery, temporary overlays
```

**Configure once in integration Options:**

| Option | Example |
|--------|---------|
| **Main menu URL** | `http://192.168.100.80:5050/Dashboard?skin=default&widget=joan_salon&count=1` |
| **Recovery probe URL** | same URL (wait for AppDaemon after HA reboot) |
| **Sync profile** (per tablet) | **Eco** for static AppDaemon dashboard |

AppDaemon updates widgets live from HA entities — you usually **do not** need content rotation or frequent `set_url` calls.

Use built-in services (`send_text`, camera snapshot, weather, …) only as **temporary overlays** with `auto_return_seconds` → return to AppDaemon.

## Purpose & overview

The integration bridges **Home Assistant** and **VSS**. It can:

- Set and guard the tablet session URL (AppDaemon, `/local/`, Lovelace, images).
- Render e-ink optimized **overlay screens** (energy, weather, calendar, buttons, PIN, RSS, …).
- Expose sensors, diagnostics, Repairs, and power/sync controls.
- Recover sessions after HA/VSS restarts without unnecessary battery drain (Eco mode).

---

## Key features

### Content & navigation
- Any URL, predefined views, local `/local/`, AppDaemon dashboards, inline `data:text/html`.
- Built-in screens: weather (3 layouts), calendar, to-do/shopping, energy panel, status panel, sensor graph, RSS, QR, crypto panel, camera snapshot.
- Interactive bottom bar (← Back / ✔ / →) or full-screen tap; webhooks to HA automations.
- Slideshow across views/URLs (use long intervals in Eco).

### Device management
- **Sync profile** per tablet: Eco / Normal / Alert.
- **Battery guard** — skip VSS PUT when URL unchanged; `wake_tablet` to force update.
- **Recovery** after reboot: HTTP probe AppDaemon → optional session restart; **Eco skip** when URL already correct.
- Safe TCLV read/apply/restore, display rotation, WebKit cache clear, sleep/wake.
- HA **Repairs** for VSS offline and orphan sessions.
- Optional **Ollama** device analysis (Options).

### Diagnostics
- `sensor.*_configured_url`, `binary_sensor.*_dashboard_ok`, offline/battery/error notifications.
- Event `visionect_joan_command_result` with `push_result`, `skipped_wake`.
- Live preview via `camera` entity.

## Installation

### Via HACS (recommended)
1. Install [HACS](https://hacs.xyz/).
2. HACS → Integrations → ⋮ → Custom repositories → add `https://github.com/Adam7411/visionect_joan`.
3. Install **Visionect Joan** → restart Home Assistant.

### Manual
1. Copy `custom_components/visionect_joan/` to `/config/custom_components/`.
2. Restart Home Assistant.

**Requirements:** VSS running (see [visionect-v3-allinone](https://github.com/Adam7411/visionect-v3-allinone)), Joan tablet registered in VSS.

## VSS & integration configuration

1. **Settings → Devices & Services → Add Integration → Visionect Joan**
2. Connection: VSS host `IP:8081`, user/password **or** API key + secret (VSS → Users → Add API key).
3. **Configure** integration Options:
   - **Views** — named URLs (e.g. `MainMenu`, `WeatherPanel`).
   - **Main menu URL** — default back target / AppDaemon dashboard.
   - **Recovery probe URL** — HTTP check before session restart after reboot.
   - **Recovery page token** — for VSS Default URL fallback page (`/api/visionect_joan/recovery`).
   - Battery / offline / error notification toggles.
4. Per tablet: set session URL (Configurator or `visionect_joan.set_url` once).

## Sync profiles & battery guard

Select entity: **Sync mode with Home Assistant** (`refresh_profile_select`).

| Profile | Use case | URL push behaviour |
|---------|----------|-------------------|
| **Eco** | Static AppDaemon dashboard (default) | Skips PUT if URL unchanged; minimal VSS polling |
| **Normal** | Occasional overlays | Guard active, medium cache TTL |
| **Alert** | Cameras, urgent alerts | Allows forced wake / faster refresh |

**Service field `wake_tablet`** (e.g. on `set_url`): force session write even in Eco.

**After HA reboot (Eco):** if AppDaemon probe succeeds and session URL matches Main menu / per-tablet view target → **no batch session restart** (saves battery).

| Type | Examples | Notes |
|------|----------|-------|
| `sensor` | state, battery, rssi, temperature, **configured_url**, last_seen, error_code | Some disabled by default |
| `binary_sensor` | online, health (orphan), is_charging, **dashboard_ok** | `dashboard_ok` = session URL matches expected AppDaemon URL |
| `select` | sync profile, view, back target, sleep schedule, push mode, encoding, dithering | Per tablet |
| `number` | reload interval (ReloadTimeout) | Session refresh seconds |
| `text` | device name | Written to VSS |
| `button` | force refresh, reboot, clear web cache | Some disabled by default |
| `camera` | live preview | Current screen PNG |

## Services summary

| Service | Description |
|---------|-------------|
| `set_url` | Set URL or predefined view; `wake_tablet`, `{uuid}` placeholder |

## Interactive layer & recovery

**Back button priority:**
1. `back_button_url` in service call
2. Per-device **Back button target** select
3. Global **Main menu URL**

**Overlays:** before pushing `data:` HTML, integration remembers current AppDaemon URL and restores it on Back / `auto_return_seconds`.

**Recovery HTTP:** if tablet cannot reach HA, set VSS Default URL to generated recovery page (Options → Recovery page).

**Offline notification:** persistent alert when tablet offline longer than threshold (1 / 4 / 24 h); updates every full hour; survives HA restart.

## Automation examples

### Static AppDaemon dashboard (once)
```yaml
service: visionect_joan.set_url
target:
  device_id: <joan_device_id>
data:
  url: "http://192.168.100.80:5050/Dashboard?skin=default&widget=joan_salon&count=1"
  wake_tablet: true   # only needed first time or after URL change
```

### Temporary alert overlay
```yaml
service: visionect_joan.send_text
target:
  device_id: <joan_device_id>
data:
  message: "Front door open!"
  text_size: 36
  add_back_button: true
  auto_return_seconds: 120
```

### Listen for push result
```yaml
trigger:
  - platform: event
    event_type: visionect_joan_command_result
action:
  - service: logbook.log
    data:
      message: "Joan {{ trigger.event.data.push_result }} skipped={{ trigger.event.data.skipped_wake }}"
```

More examples (PIN, energy panel, slideshow): see previous sections in Git history or Polish README.

## Performance & battery

| Topic | Recommendation |
|-------|----------------|
| **Daily use** | AppDaemon URL + profile **Eco**; avoid repeated `set_url` |
| **Overlays** | Use `auto_return_seconds`; avoid leaving overlay permanently |
| **Slideshow** | ≥ 300 s per slide in Eco; shorter intervals drain battery |
| **ReloadTimeout** | 60–300 s for dynamic pages; high values for static AppDaemon |
| **Recovery** | Set **Recovery probe URL** to AppDaemon; Eco skips redundant restarts |
| **Sleep** | Use tablet sleep schedule + `sleep_device` overnight if needed |

## Troubleshooting

| Issue | What to check |
|-------|----------------|
| Connection refused after HA reboot | Recovery probe URL, AppDaemon running, log: `Eco recovery skip` or `session batch restart` |
| Tablet shows wrong page | `sensor.*_configured_url`, `binary_sensor.*_dashboard_ok`, run `set_url` |
| Button/webhook ignored | Automation trigger `webhook_id`, Developer Tools → Events |
| Offline alert wrong hours | Reload integration (v3.9.13+); guard state persisted on disk |
| Screen stale | `force_refresh` or adjust ReloadTimeout |
| VSS / orphan issues | **Settings → Repairs**; integration health notifications |

Debug logging:
```yaml
logger:
  logs:
    custom_components.visionect_joan: debug
```

## FAQ

**Best setup for a fixed dashboard?**  
[joan_generator](https://github.com/Adam7411/joan_generator) + AppDaemon + `set_url` once + Eco profile.

**Do button panels show live states?**  
No — stateless webhooks. Use AppDaemon or `send_status_panel` for live data.

**Does integration rotate content on a schedule?**  
Not by default — AppDaemon handles live widgets. Use automations or slideshow if needed.

**Other Joan models?**  
Tested on Joan 6 / 13 PRO.
