## Recommended setup (AppDaemon)

Most users keep the tablet on a **single AppDaemon dashboard** generated by the **Joan Dashboard Generator** add-on:

```
joan_generator → *.dash files → AppDaemon :5050 → tablet (VSS session URL)
visionect_joan → battery, recovery, alerts, temporary overlays (send_*)
```

| Setting | Where / example |
|---------|-----------------|
| AppDaemon URL | `http://192.168.100.80:5050/Dashboard?skin=default&widget=joan_salon&count=1` |
| **Predefined view** | **Configure Visionect Joan** → **Manage views** — e.g. name `MainMenu` with the AppDaemon URL above |
| **Back button target** | Per-tablet select — same view or URL |
| **Sync profile** (select per tablet) | **Eco** |

AppDaemon refreshes widgets from HA entities — you **do not** need to call `set_url` repeatedly. Use `send_*` services as **short overlays** with `auto_return_seconds`.

Configure everything under **Settings → Devices & Services → Visionect Joan → Configure** (views, recovery page, notifications).

## Purpose & overview

The integration acts as a bridge between Home Assistant and Visionect Software Suite (VSS). It generates dynamic, e-ink optimized screens on Joan 6 / 13 PRO that react to context (events, zones, time, sensors). Instead of a plain dashboard you can push a *fully rendered* view: energy panel, interactive to-do list (webhook toggle), history graph, weather section with chart, PIN keypad, crypto panel, or 12-button panel.

It also monitors tablet state, battery, VSS orphan sessions, offers **HA Repairs**, and **Eco recovery** after Home Assistant restarts.

---

## Key features

- Full screen control: any URL, local pages (AppDaemon, `/local/`, Lovelace panel embed), images, inline HTML `data:` URLs.
- E-ink optimized views:
  - Weather: detailed, forecast list, 24h chart panel.
  - Calendar: day list, minimal, monthly grid + day preview.
  - To-do / Shopping List with interactive toggle via webhook.
  - Energy panel (usage, production, import, export, consumption).
  - Entity status panel (icons + names + values + translated states).
  - Sensor history graph (line / bar) with automatic orientation.
  - RSS / Atom — paginated.
  - QR code (e.g. guest Wi‑Fi).
  - **Crypto panel** (CryptoCompare + sparkline).
  - PIN keypad (webhook → automation verifies code).
  - 12-button panel (stateless — each button triggers its own webhook).
- Interactive layer: bottom bar (← Back / ✔ center / → right), or full screen as “tap to action” / “tap to back”.
- Live preview (`camera`) — current screen snapshot as camera entity.
- **`dashboard_ok`** entity — whether session URL matches AppDaemon / Main menu.
- **Eco / Normal / Alert** profiles + **battery guard** (skip PUT when URL unchanged).
- UI settings: predefined views, notifications, recovery page, Ollama.
- Management: screen rotation, WebKit cache clear, force refresh, sleep/wake.
- Rendering parameters: dithering, encoding (bit depth).
- Safe Config TCLV (read / write / restore backup).
- Temporary file cleanup (snapshots / graphs) in `www/`.

## Installation

### Via HACS (recommended)

1. Install [HACS](https://hacs.xyz/) if you do not have it yet.
2. HACS → Integrations → click ⋮ → Custom repositories.
3. Add repo: `https://github.com/Adam7411/visionect_joan` as “Integration”.
4. Find “Visionect Joan” → Install.
5. Restart Home Assistant.

### Manual

1. Download the latest release (`visionect-joan.zip` or “Source code”).
2. Extract to: `/config/custom_components/visionect_joan/`.
3. Restart HA.

**Requirements:** VSS ([visionect-v3-allinone](https://github.com/Adam7411/visionect-v3-allinone)), tablet registered in VSS, optionally AppDaemon + joan_generator.

---

## Visionect Software Suite (VSS) configuration

1. Go to `Settings → Devices & Services`.
2. Click **“+ Add Integration”**.
3. Search for **“Visionect Joan”** and start setup.
4. Enter Visionect Software Suite credentials: [VSS installation guide](https://github.com/Adam7411/Joan-6-Visionect_Home-Assistant_EN)
   - Server address (e.g. `http://192.168.x.x:8081`) — VSS address (usually same host as HA)
   - Username (`admin`)
   - Password (set your own)
   - API Key and API Secret (VSS → Users → Add new API key)
5. **Configure** the integration (views, recovery, notifications).
6. Set the tablet URL once — usually AppDaemon (`set_url` with `wake_tablet: true`).

## Integration options (UI)

**Settings → Devices & Services → Visionect Joan → Configure**

| Menu | What you configure |
|------|-------------------|
| **Manage views** | Add / edit / delete views (name + URL) |
| **Default URL** | Recovery page token — paste URL into VSS → Settings → HTML Backend → Default URL |
| **Cache and disk cleanup** | Age of temp files in `www/` |
| **Tablet language** | PL / EN / DE / … / Auto |
| **Notifications** | Battery, ErrorCode, offline, orphan |
| **Ollama log analysis** | URL, model, interval (optional) |

### Notifications submenu

| Section | Parameters |
|---------|------------|
| **Battery** | Threshold 5/10/15 %; on-tablet alert; HA notifications; battery guard interval |
| **Errors (ErrorCode)** | HA notification on VSS error code |
| **Offline** | Enable/disable; threshold 1 / 4 / 24 h (hourly update, v3.9.13+) |
| **State / orphan** | Automatic notification on session issues |

## Predefined views

Save views in Integration Options:

1. Settings → Devices & Services → Visionect Joan → Configure.
2. “Add view” → Name + URL.
3. Use these names via the `Choose view` select entity or pass as `predefined_url` / `url` in services.

Legacy format (“Name: URL” line by line) is migrated automatically.

## Sync profiles & battery guard

**Select: Sync mode with Home Assistant**

| Profile | When to use | Behaviour |
|---------|-------------|-----------|
| **Eco** | Static AppDaemon dashboard (default) | Minimal polling; **no** PUT to VSS when URL unchanged |
| **Normal** | Occasional overlays | Battery guard active |
| **Alert** | Cameras, urgent alerts | Faster refresh |

**Service `set_url`:** field **`wake_tablet: true`** — forces session write even in Eco.

**Eco recovery (v3.9.14):** after HA restart, when AppDaemon probe OK and session URL correct → skips unnecessary VSS session restart.

**Event:** `visionect_joan_command_result` — includes `push_result` (`success`, `skipped_unchanged`, `skipped_guard`).

## Interactive layer & back priority

Back target priority:

1. `back_button_url` (in service call)
2. Per-device **Back button target** select
3. Predefined view from **Integration Options** (Manage views) or per-tablet **Choose view** select

Hiding visible buttons:

- `click_anywhere_to_action: true` → full screen = action (webhook).
- `click_anywhere_to_return: true` → full screen = back.

Enabling either option hides the bottom bar.

**Overlay → AppDaemon:** before `send_*` the integration remembers current URL; `auto_return_seconds` or ← restores the dashboard.

**Recovery after HA restart:** HTTP GET on AppDaemon view URL (from selects / options) → Eco skips session restart when URL OK → safety net 5/8/10 min.

## Performance & battery

| Element | Recommendation |
|---------|----------------|
| **Daily use** | AppDaemon + **Eco** profile; avoid repeated `set_url` |
| **`wake_tablet`** | `true` only on first URL setup or intentional wake |
| `ReloadTimeout` | 60–300 s for info panels; high values for static AppDaemon |
| Slideshow | ≥ 120 s in Eco; ≥ 30 s in Normal |
| Encoding | `1` for text / simple views; `4` for photos and shaded graphs |
| Dithering | `none` for readability; `floyd-steinberg` for images |
| Large images | Scale to screen resolution before sending |
| Recovery | AppDaemon view in **Configure Visionect Joan** + **Choose view** / **Back button target** selects |
| Night | Tablet sleep schedule; `sleep_device` optional |
| Sleep | Use `sleep_device` when tablet does not need updates for a while (e.g. overnight) |

## Security & webhooks

- HA webhooks (`/api/webhook/<id>`) are not authenticated by default — treat them as local triggers.
- Do not expose port 8123 publicly without reverse proxy / authorization.
- For sensitive actions use random identifiers (`joan_action_9342hf` etc.).
- Do not log PINs — compare via templates or store in `input_text`/secrets.
- Separate host? Ensure correct `internal_url`, otherwise webhook may be built incorrectly.
- Recovery page token — treat like a password.

## Troubleshooting

| Problem | Cause | Solution |
|---------|-------|----------|
| Button no reaction | Wrong `webhook_id` / missing automation | Events → check `webhook` input |
| Screen not refreshing | Stale session | `force_refresh` or change `ReloadTimeout` |
| Connection refused after HA restart | AppDaemon unavailable | Check view URL in options; log `Eco recovery skip` |
| Wrong screen | Wrong session URL | `sensor.*_configured_url`, `binary_sensor.*_dashboard_ok` |
| Offline alert always “4 h” | Old bug (fixed v3.9.13) | Reload integration |
| Stale images / CSS | WebKit cache | `clear_web_cache` (+ optional restart) |
| Empty graph | No history / recorder disabled | Enable history for sensors |
| Wrong rotation | Session not reloaded | After `set_display_rotation` + reboot |
| PIN always wrong | Automation not receiving JSON | Check `trigger.json` in Template Editor |
| RSS feed empty | Feed unavailable / network error | Open URL in browser, check logs |
| Orphan / VSS | Session issue | HA Repairs; **Check health** button |

Enable debug:

```yaml
logger:
  logs:
    custom_components.visionect_joan: debug
```

After YAML changes: **Check configuration** in HA.

## FAQ

**Best setup for a fixed dashboard?**  
[joan_generator](https://github.com/Adam7411/joan_generator) + AppDaemon + one-time `set_url` + Eco.

**Can buttons show device states (e.g. lights)?**  
Currently the 12-button panel is stateless (no feedback). For live states use status panels, AppDaemon, or custom dashboards.

**Ghosting on screen — normal?**  
Frequent e-ink refreshes cause artifacts. Limit update frequency and use higher contrast (encoding=1).

**Can I use other Joan models?**  
Tested on Joan 6 / 13 PRO. Other models may work partially — no official tests.

**Why does an external site not show in slideshow?**  
Many domains block iframe (CSP / X-Frame-Options). Use local URLs / predefined views.

**Can I send custom HTML?**  
Yes — `data:text/html,<html>...</html>` as URL in `set_url` or auto-generated by services.

**Does the integration rotate content on its own?**  
Not by default — AppDaemon refreshes widgets. Slideshow/automations optional.
